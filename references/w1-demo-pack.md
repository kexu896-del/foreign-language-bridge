# W1 全流程示范包（合成示例）

> 合成示例：人物、公司、日期、金额均为虚构；仅用于展示预习卡、会话、报告与卡片的质量标准，**不是真实会话证据，也不要背稿**。
> 设定：20 分钟 / 中级 / 引导式 / 语音；主题 W1 项目启动会。

## 一、预习卡（示例）

**场景**：你作为买方项目负责人，与供应商项目团队开 20 分钟启动会，说明目标、范围、时间与下一步。

**角色**：你（买方负责人）；对方（供应商项目经理 + 一名技术负责人）。

**任务**：让对方在会后能复述目标、两个约束、负责人与下一步。

**成功标准**：对方能说出“做什么/不做什么、何时、谁确认、下一步”；你不对未确认事项做保证。

**关键词（30，识认词库，不要求全部用出）**

| 项目 | 时间 | 风险/边界 | 沟通 |
| --- | --- | --- | --- |
| scope 范围 | milestone 里程碑 | dependency 依赖 | agenda 议程 |
| deliverable 交付物 | deadline 截止时间 | assumption 假设 | minutes 会议纪要 |
| baseline 基线 | lead time 提前期 | constraint 约束 | action item 行动项 |
| rollout 上线推广 | cutover 切换 | contingency 应急方案 | follow-up 跟进 |
| pilot 试点 | buffer 缓冲 | risk register 风险登记 | point of contact 联系人 |
| acceptance criteria 验收标准 | SLA 服务级别 | escalation 升级路径 | sign-off 签批 |
| change request 变更申请 | workstream 工作流 | blocker 阻塞项 | stakeholder 相关方 |
| backlog 待办池 |  |  | kickoff 启动会 |

**词组（8）**

- `The purpose of today's call is to...` 今天会议的目的是……
- `To be clear on scope...` 把范围说清楚……
- `What's not included is...` 不包含的是……
- `The main constraint is...` 主要约束是……
- `We need your confirmation on...` 我们需要你确认……
- `Let's park that and come back to it.` 先搁置，稍后回来。
- `Who owns this on your side?` 你们这边谁负责？
- `I'll send a short recap after the call.` 会后我发一份简短纪要。

**句型（5）**

1. `The purpose of today's call is to align on scope, timeline, and next steps.`
2. `The first release covers A and B; the mobile app is out of scope for now.`
3. `Our timeline depends on your security review, so we need a fallback.`
4. `Could you confirm the data fields and the owner by Friday?`
5. `I can't guarantee the June date today; I'll confirm after the review.`

**可能的问题（5）**

1. What's the timeline?
2. Who signs off on your side?
3. What if we find a missing requirement later?
4. What do you need from us by Friday?
5. Can you guarantee the June date?

**难点**：供应商可能压时间；你要区分“可确认”与“需回去确认”，不越权承诺。

**挑战**：主动用出 6 项表达，并处理一次“范围变更”追问。

## 二、会话片段（示例，已脱敏）

> 教练扮演供应商项目经理；示例学习者使用引导式提示。发音未提供音频，本示例不评价发音。

**教练**：Thanks for joining. Give me the short version—what are we trying to achieve?

**学习者**：Yes. The purpose of today's call is align the project plan.

**教练**：A natural way is “The purpose is to align…”. Great—go on.

**学习者**：We want to launch the new platform in June. The first release covers intake and reporting. What's not included is the mobile app.

**教练**：Good. And the timeline? We heard June, but we have a dependency on your security review.

**学习者**：Right. The main constraint is the security review. If it slips, we need a fallback.

**教练**：What do you need from us by Friday?

**学习者**：We need your confirmation on the data fields, and… who is owning this on your side?

**教练**：Natural: “who owns this on your side.” Keep going.

**教练**：One more—if we find a missing requirement in week two, what happens?

**学习者**：（停顿）

**教练（中文意图提示）**：说明变更走什么流程、谁来批准。

**学习者**：We need a change request, and the steering group approves it.

**教练**：Last one: can you guarantee the June date?

**学习者**：I can't guarantee it today. I'll confirm after the security review, and send a recap with owners and dates.

**学习者**：Let's wrap up.

## 三、收口报告（示例）

**会话**：W1 项目启动 / 20 分钟 / 中级 / 引导式 / 语音；任务完成：对方能复述目标、约束、负责人与下一步。

**具体亮点**

1. 主动用 `What's not included is...` 划出范围边界。
2. 面对“能否保证 6 月”时用 `I can't guarantee it today` 守住边界，并给出确认路径。

**目标覆盖**

| 目标表达 | 独立 | 中文提示后 | 关键词/框架后 | 模仿 | 未出现 |
| --- | --- | --- | --- | --- | --- |
| purpose | ✓ |  |  |  |  |
| scope boundary | ✓ |  |  |  |  |
| constraint | ✓ |  |  |  |  |
| fallback | ✓ |  |  |  |  |
| confirmation request | ✓ |  |  |  |  |
| owner |  |  | ✓ |  |  |
| change request |  | ✓ |  |  |  |
| recap | ✓ |  |  |  |  |

**表达复盘**

- 保留：`What's not included is the mobile app.`（边界清楚）
- 修复：`The purpose is align...` → `The purpose is to align...`（purpose 后接不定式）
- 修复：`who is owning this` → `who owns this`（状态动词用一般现在时）

**掌握度**：developing（多数目标在提示/轻修复后完成；`owner` 需再测）。教练示范不算掌握。

**下次重点（最多 3 条）**

1. 用 `What's not included...` 主动划范围，不等对方问。
2. 时间被压时给 fallback，而不是重复“我们尽量”。
3. 结束前用“owner + date”复述行动项。

**下次练习（2–5 分钟）**：同一场景，新增“预算被砍 20%”约束，要求用 3 句话说明取舍；回答一个陌生追问。

## 五、证据卡（示例）

```markdown
# Speaking Evidence — 示例（合成）
真实场景：W1 供应商启动会（虚构）
任务：说明目标/范围/时间/下一步
听众与关系：供应商项目经理与技术负责人
结束后对方要做什么：复述目标、两个约束、负责人与下一步
允许：提纲（是）/重录（否）/AI（仅复盘）/录音（是）
参考变体：英式/美式混合材料；不强制模仿
设备：耳机麦；安静房间；听众不熟悉我的口音

## 三种基线
本次为单次情景练习，未做完整基线；下次补独白 + 五轮问答 + 修复。

## 听众复述（教练模拟）
主旨：6 月上线核心模块，移动端暂不包含
细节：安全审查是依赖；周五前确认数据字段
需要重听：`owner` 一处表达
下一步：供应商确认负责人并回传日期

## 高影响问题
| 时间 | 对方可能听成 | 我的原意 | 类型 | 任务影响 | 本轮动作 |
| --- | --- | --- | --- | --- | --- |
| 05:10 | who is owning | 谁负责 | 语法/自然度 | 低（可理解） | 已修复，卡片复练 |

## 结论
当前证据支持：继续同一场景 + 增加时间压力
不能推出：真实会议能力、发音/流利度水平
下一项最小任务：带“预算削减”条件重做 3 分钟简报
复查：7 天后换听众复测
```

## 六、使用方式

1. 用你自己的主题生成预习卡，对照本示例检查：场景/角色/任务、词库数量、词组与句型是否分层、是否有一个挑战。
2. 不要照抄示例句子；报告只引用你实际说过的内容。
3. 第一次真实会话后，对照本示例看报告是否具备：具体亮点、覆盖表、原句 vs 修复、≤3 条重点、一个迁移任务。
4. 示例中的“教练模拟听众复述”只用于格式演示；真实训练应尽量找真人或至少录音回听。
